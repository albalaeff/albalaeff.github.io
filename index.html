Built in a team of two.

The idea and the original spec came from my teammate. I turned the spec into a working product in two days, then kept building.

Version one in two days

On 30 September and 1 October I built the first working version end to end: database, offer feed, responses, deals and ratings, notifications, moderation, a web admin with two-factor login, Docker and tests.

Interface and design

Bot flows and the admin panel: the redesign, the mobile version, the System and Stats sections, ban management, and an Android admin app in Kotlin with Jetpack Compose.

Trust and safety

An encrypted log of every deal chat, phone and Telegram account checks against the CAS and LOLS spam databases, weighted reputation, a risk score that alerts moderators, and deal complaints.

Rates and languages

Market rates from ExchangeRate-API, exchange-office rates from BestChange, Revolut and Wise for comparison. The bot reads amounts written as text, like “1000 euro” or “€1000”. I also added Ukrainian and the language packs.

Test infrastructure

I laid the groundwork for testing: database fixtures, a test bench for the bot, and end-to-end tests that run the bot, the worker and the admin together.

Tooling for AI agents

Environment checks, a map of every screen, and automatic handoff between agent sessions, so each new session picks up exactly where the last one stopped.

Agents write the code.
I own the result.

On Personal Exchange Bot every change runs through the same loop: one GitHub issue, one coding agent, one fresh session. People stay in the loop through the issue thread.

  1. Open an issue

    Every task starts as a GitHub issue. Its labels set how strong the agent is, using Claude Code’s own values.

    model:opuseffort:xhigh

  2. Start an agent

    A session manager runs the repo’s issue watcher and starts one headless Claude Code agent per issue, in its own git worktree and a fresh session.

  3. Confirm the task

    Before it writes any code, the agent reviews the issue and posts a comment with how it understood the task, plus sample screens where relevant. If something needs discussing, it happens in that thread.

  4. Build

    The agent writes the code and the tests on its own branch and delivers them as a pull request through the repo’s existing workflow.

  5. Verify

    CI on GitHub Actions runs ruff, mypy, the full pytest suite and a gitleaks secret scan. Then a person reviews the result.

  6. Hand off

    When it finishes, the agent leaves a handoff for the next session. Agents talk to each other through issue comments, in plain language anyone can read.
