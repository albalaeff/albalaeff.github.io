Rubles abroad: no banks, only chats.

Since the 2022 sanctions, most banks and exchange offices in Europe no longer exchange rubles. Yet many Russians live abroad and need local money, like Czech koruna. Until now they swapped it in Telegram chats.

Trust is the product

Exchange chats are full of scammers, and people meet strangers to swap cash. These are the safety features I built so they can trust each other.

  • Encrypted deal log

    Every deal chat is logged, and the log is encrypted.

  • Account checks

    Phone verification, Telegram account age, and lookups in the CAS and LOLS spam databases.

  • Weighted reputation

    A reputation score built from weighted ratings.

  • Risk score

    A risk score that alerts moderators.

  • Complaints

    Users can file a complaint about a deal.

My role

The idea and the original spec came from my teammate. We write the issues, make the decisions and check the results; Claude Code agents write the code and the tests. 153 of the 365 commits and 103 of the 327 merged pull requests are mine.

What I built

  • Version one in two days. From the spec, on 30 September and 1 October: project skeleton, database, bot, offer feed, responses, deals, ratings, notifications, moderation, the web admin with two-factor login, Docker and tests.
  • Interface and design. Admin redesign, mobile version, System and Stats sections, ban management, and the Android admin app.
  • Trust and safety. Encrypted deal log, account checks, weighted reputation, risk score, complaints.
  • Rates and languages. Rate sources, reading amounts like “1000 euro” or “€1000” from text, Ukrainian and the language packs.

How we work with agents

  • One issue, one agent. A session manager watches the repo and starts a headless Claude Code agent for each GitHub issue, in its own git worktree and a fresh session.
  • Labels set the power. Issue labels pick the model, from model:haiku to model:opus, and the effort, from effort:low to effort:max. Without labels the agent runs on Opus at xhigh effort.
  • Confirm before coding. The agent posts how it understood the issue, with sample screens where relevant, and only then starts coding.
  • Plain-language handoffs. Agents hand off to the next session and talk through issue comments a person can read.
  • Tooling I built for them. Environment checks, a map of all 173 screens and automatic handoff between sessions.
